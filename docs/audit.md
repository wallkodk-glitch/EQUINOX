# EQUINOX v1 audit and model decisions

The user specification is authoritative except where corrected here with explicit reasoning.

1. Capital identity in section 27 omitted an equals sign. Implement buys + zero fees + residual = new capital.
2. BUY-01's decimal weights sum to 0.99999999. Fixture weights are explicitly normalized before deriving a solution; no display rounding is reused.
3. Continuous L2 is a Euclidean projection of `target*(V+C)-v` onto the nonnegative simplex of mass C. Strict convexity gives a unique buy vector for V+C>0.
4. Execution's canonical objective retains denominator V+C (fees=0) and sums squared deviations over the five assets only. Residual cash is held separately; no cash penalty is added to the objective. Risky weights for reporting/risk use sum(projected asset values). Both denominators and both deviation metrics are exposed. Greedy increments follow the requested algorithm, including a feasible purchase with negative improvement if necessary. This is deterministic local discrete execution, not a claim of global integer optimum.
5. If no risky capital exists, weights and risk contributions are undefined and represented by null, never fabricated zeros. C=0 with V>0 returns no buys. V=C=0 returns NO_CAPITAL.
6. Raw ERC uses positive risk-budget coordinate descent, equivalent to ERC for positive-definite covariance, and explicitly validates the requested RC-share objective. Constrained ERC minimizes that exact objective using deterministic projected gradient with analytic gradient and multiple fixed starts. A projected first-order stationarity residual is required; no global-optimum certificate is claimed for the nonconvex constrained problem.
7. For Equal Weight and Inverse Volatility, policy application means Euclidean projection onto the supported bounded simplex plus a combined BTC/ETH cap. This is a human policy projection, separate from raw targets. Default policy has no restrictive cap/floor.
8. V1 rejects singular or condition number >1e12 covariance for volatility-dependent target solvers. Equal Weight is independent of covariance; risk analytics may be unavailable separately. Material negative eigenvalues fail; tiny negative eigenvalues may be explicitly repaired and both matrices retained.
9. 95% coverage does not permit silently joining two nonconsecutive sessions into a daily return. Only consecutive canonical pairs contribute returns; missing pairs are reported; minimum 252 daily returns is also enforced.
10. Default fees are explicitly ZERO_FEE_V1, no spreads/slippage/ADR fees/taxes. Prices are indicative inputs. Order precision is user-confirmed instrument metadata, never inferred from a broker.
11. No authenticated GitHub repositories were returned by the connector. Prepare source, reproducible build and Pages workflow; do not claim hosted deployment without access.
12. Node/Chromium cross-runtime testing reproduced an eigenvalue difference of approximately 1.7e-18. Bit-identical replay was an incorrect requirement for derived transcendental calculations. Replay now records `FLOAT64_REPLAY_V1`: absolute tolerance 1e-12 plus relative tolerance 64 times machine epsilon for derived analytics. Inputs, structure, model versions, solver iteration/configuration integers, executable orders, spend, fees and residual cash remain exact. The original frozen snapshot and its exact SHA-256 are preserved; regeneration never overwrites historical values with another runtime's last bits. This is integrity checking, not an authenticity signature.
13. Discrete execution uses an exact 10^-16 DKK integer cost lattice from eight-decimal price and quantity inputs. Cash gains are batched only across descending quadratic marginal-gain sequences, retaining deterministic tie handling. A default-precision regression and 120 bounded comparisons against literal one-increment greedy execution protect this optimization. Precision beyond eight decimals is rejected; sub-øre accounting is theoretical and does not imply broker settlement precision.
