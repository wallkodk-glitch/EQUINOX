# Security and data boundaries

Credentials: dedicated localStorage namespace, isolated from financial IndexedDB. Two small user-supplied keys need no database migration. This is plaintext-at-rest browser storage, NOT secure secret storage. Same-origin scripts/XSS, extensions, profile readers or device access can expose keys. Browser-level backups/sync are outside app control. Use limited/read-only keys when available; revoke with the provider after suspected compromise. Removal deletes the app entry, not forensic copies. JavaScript cannot promise secure memory erasure; editing inputs and auth headers necessarily exist transiently in memory/devtools.

The password dialog never reveals or prepopulates a saved key. Cancel/save clears and unmounts input. Editing a tested draft invalidates its test message. Saved does not mean Connected; reload requires another test. No startup popup. Only allowlisted static error codes are displayed/persisted; raw provider text, URLs, headers and causes are discarded.

Transport: fixed HTTPS provider destinations; Massive Authorization Bearer; CoinGecko x-cg-demo-api-key; no key to Nationalbank. No cookies, redirects, referrers or HTTP caching. Secret-named queries and active key echoes in pagination URLs reject. Timeout 15 seconds, abort propagation, bounded 100-page pagination, no retries. Massive pacing is 13 seconds per request per tab with 60-second cooldown after 429; it is NOT account-wide coordination. The UI prevents overlapping local jobs. Cross-tab storage changes abort pending work and invalidate provider state.

Raw payloads are transient. Only allowlisted normalized observations enter separate IndexedDB `EQUINOX_MARKET_DATA_V1`. Raw data, account IDs, errors, headers and unknown fields are not cached. This is an explicit raw/normalized boundary, not an archival raw-response database. Rows retain provider/instrument, schema/model version, normalized value/unit, semantics, source URL, economic date, documented timestamp roles and actual acquiredAt. Freshness is computed from stored facts rather than persisted as a status that ages incorrectly.

Observation date, observation timestamp, provider timestamp and acquisition time are separate. Daily stock timestamps remain window starts; unverified actual close timestamps stay null. Crypto minute bucket start/end are explicit and do not claim a trade exactly at the endpoint. Nationalbank date-only timestamps remain null; RSS noon is not publishedAt. Cache validates provider/instrument/currency/time roles, stock date/midnight/calendar/acquisition consistency, future observations and same-identity conflicts atomically. Exact duplicates preserve original provenance; corrections require future explicit review, not silent overwrite.

Statuses: CURRENT (recent crypto reference), EOD, CACHED, STALE, OFFLINE; never LIVE. Crypto age limit 15 minutes, FX request limit 120 hours and display conservative four-calendar-day limit; equities/minute references must match latest available session for EOD. Offline remains visible with observation/acquisition timestamps. No status authorizes automatic risk use in this candidate. There is no cache eviction/correction workflow yet; browser eviction can remove data. Export financial backups separately.

The worker caches packaged static shell URLs only. External, authenticated and query-bearing requests bypass it. It never persists authenticated API responses. Financial backups/recovery/snapshots exclude credentials and reference cache, including poisoned restore attempts. Financial state/snapshot schema and Engine are unchanged: no migration. New prices cannot mutate holdings, covariance/ERC or immutable calculations. Calculation Details says only its stored inputs are used; full provider-backed snapshot provenance is BLOCKED because no risk bridge exists.

Runtime-generated synthetic keys are checked against UI/errors/logs, financial backup, snapshot, normalized/cache storage and production files. Their passing tests are not real-account authentication evidence. No actual user keys were available to scan or test. Neither encryption theatre, backend, cloud login nor telemetry was added.
