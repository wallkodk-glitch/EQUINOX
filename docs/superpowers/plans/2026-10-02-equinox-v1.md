# EQUINOX v1 Implementation Plan

**Goal:** Independently validated DKK capital allocation with a mobile offline interface.
**Architecture:** Data truth → mathematical target → execution → immutable proof. React consumes pure TypeScript functions. IndexedDB stores versioned inputs and append-only calculations.
**Spec:** User's 56-section EQUINOX v1 build specification, with explicit audit rulings in `docs/audit.md`.
**Execution:** Native implementation, independent Python reference audit and provider research in parallel; final fresh review. The user's explicit build mandate supersedes additional design/plan approval checkpoints.

## Global constraints
DKK; assets GOOGL/ISRG/TSM/BTC/ETH; buy-only; simple returns; annualization 252; no backend, account, telemetry, secrets or trading; fee model exactly zero; no silent fallback.

## Review focus
- Cash denominators when whole shares prevent full investment.
- Imported provenance does not establish truth of market observations.
- Empty portfolios and capital=0 do not have defined risky weights.
- Stale results following edits must not look current.
- Corrupt storage, multi-tab updates and interrupted writes must preserve state.

## Tasks
1. Audit: independent Python FX, covariance, ERC and buy fixtures. Save reproducible references. Resolve rounding, PSD, constrained stationarity, data calendars, fees and cash semantics before code.
2. Engine: tests first in `tests/engine.test.ts`; implement `risk/`, `optimization/`, `execution/`, `portfolio/`. Verify analytic vectors, independent constrained solution, invariants and edge failures. No material math failures carried forward.
3. Data: `market-data/` adapter interface, canonical US close calendar, explicit raw-close/split/dividend and FX rules, runtime schema, fail-closed quality gate; tests for timestamps, missing data, events, freshness and semantics.
4. Proof and persistence: `snapshots/` deterministic regeneration and deep immutable snapshots; `persistence/` IndexedDB atomic writes, revisions, schema migrations, validation, backup/restore and recovery tests.
5. App: `ui/` mobile portfolio inputs, three model choices, execution/policy configuration, current/target/projected comparison and full calculation details. No formatting enters the Engine.
6. Release: manifest, generated service worker, content-versioned offline shell, prompted updates, dark/light, mobile browser tests, GitHub Pages CI workflow and complete source ZIP. Separate browser/build/math/physical-iPhone/deployment evidence.

## Verification commands
`python3 reference/reproduce.py`; `npm ci`; `npm run lint`; `npm run typecheck`; `npm test`; `npm run build`; `npm run test:browser`.
Expected: each exit 0. Physical iPhone and hosted deployment only PASS after real evidence.
